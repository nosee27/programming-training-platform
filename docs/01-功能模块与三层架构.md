## 0. 阶段确认

### 0.1 角色与开发方式

- 定位：资深全栈架构师 + 高级前端工程师，负责本项目的**迭代式**开发。
- 方式：所有代码沉淀在**同一个工程**中，通过 Git 做版本控制；每次迭代只做「增量补充」，不另起项目、不重写已定稿部分。
- 交付顺序严格按：功能模块图 → 三层架构图 → ER 图与表结构 → 前端界面 → 一键登录与路由守卫。

### 0.2 技术栈（第 2 次修订后的统一口径）

| 分层 | 选型 |
| --- | --- |
| 前端 | **原生 HTML5 + CSS3 + JavaScript（ES6+），多页面应用（MPA），零框架、零 UI 库** |
| 前端交互 | 原生 DOM API 手写侧边栏折叠、Tab 切换、表格、分页器、弹窗、表单校验 |
| 前端请求 | 原生 `fetch` 统一封装（`assets/js/api.js`） |
| 前端存储 | `localStorage` 存 token 与用户信息，`sessionStorage` 存页面级筛选条件 |
| 前端路由守卫 | `assets/js/auth-guard.js`，每个页面 `<head>` 内引入，校验 token + 页面权限码 |
| 后端 | Node.js + Express（接口层 / 业务层 / 数据访问层分离） |
| 数据访问 | `mysql2/promise` + 手写 SQL（与 `sql/01-schema.sql` 一一对应） |
| 数据库 | MySQL 8.0（utf8mb4 · InnoDB） |
| 鉴权 | 一键登录 + JWT |

### 2.2 一次请求的调用时序（一键登录 → 加载学生列表）

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户（浏览器）
    participant P as 表现层<br/>login.html / auth-guard.js
    participant R as 接口层<br/>routes/student.js
    participant S as 业务层<br/>services/studentService.js
    participant D as 数据访问层<br/>dao/studentDao.js
    participant DB as MySQL

    U->>P: 点击「一键登录」
    P->>R: POST /api/auth/one-key-login
    R->>S: oneKeyLogin()
    S->>D: 查询默认账号 + 角色 + 权限码
    D->>DB: SELECT 联表查询
    DB-->>D: 用户 / 角色 / 权限集合
    S->>S: 生成 JWT（含 adminId、roleCode、有效期 7 天）
    S-->>R: token + 用户信息 + 权限码数组
    R-->>P: 统一响应体 { code:0, data, message }
    P->>P: localStorage 写入 token，跳转 index.html

    U->>P: 进入「学生管理 - 基本信息」
    P->>P: auth-guard.js 校验 token 与页面权限码 student:basic:list
    P->>R: GET /api/students?page=1&size=10（Header: Authorization Bearer）
    R->>R: JWT 认证中间件 + 权限校验中间件
    R->>S: listStudents(query)
    S->>D: findPage(条件, 分页)
    D->>DB: SELECT ... LIMIT 0,10（预编译）
    DB-->>D: 结果集 + 总数
    D-->>S: rows / total
    S-->>R: PageResult
    R-->>P: 200 统一响应体
    P-->>U: 原生 JS 渲染表格 + 分页器
```

### 2.3 三层职责边界（便于答辩说明）

| 层 | 职责 | 不该做的事 |
| --- | --- | --- |
| 表现层（浏览器 / APP） | 页面渲染、交互、表单校验、动态菜单、路由守卫、token 携带 | 不写业务规则、不直连数据库、不硬编码权限判断 |
| 事务处理封装层 | 参数校验、鉴权、业务规则、事务边界、缓存读写、统一响应与异常 | 不拼接 SQL 造成注入、不把裸实体直接返回前端 |
| 数据层 | 数据持久化、索引与约束、事务日志、缓存与会话存储 | 不包含业务判断逻辑 |
