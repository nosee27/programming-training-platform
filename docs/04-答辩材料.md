# 答辩材料（讲解稿 + 演示脚本 + 常见追问）

项目：**编程培训平台管理平台**（江京教育）
一句话定位：面向编程培训机构的一体化管理平台，覆盖系统管理、新闻中心、教师、学生、课程、班级、成绩、课件资源八个模块，并作为父系统向下挂载编程环境、评测考试、我的题库等子系统。

---

## 一、1 分钟开场话术

> 我们的项目叫「编程培训平台管理平台」，是用 AI 辅助迭代开发完成的。
> 技术上采用**三层架构**：前端是纯 HTML/CSS/JS 的静态页面层，中间是 Node.js + Express 的事务处理封装层（接口层 / 业务服务层 / 数据访问层），底层是 MySQL 8.0。
> 登录采用**一键登录**：不输入账号密码、不选择角色，点击即进入，后端签发 JWT 并把权限码写进令牌，前端按权限码渲染菜单与按钮。
> 整个项目分五轮迭代，所有代码沉淀在同一个工程里，用 Git 做版本控制，并且内置了 4 个自检脚本保证「文档、代码、数据库」三者一致。

## 二、三层架构讲解稿（对着 docs/01 的架构图讲）

| 层 | 我们的实现 | 一句话说明 |
| --- | --- | --- |
| 第一层 表现层 | `web/` 下 27 个静态页面 + 7 个公共 JS | 只负责渲染与交互：`layout.js` 画框架、`components.js` 提供组件、`page-list.js` 渲染列表、`auth-guard.js` 做页面级守卫 |
| 第二层 事务处理封装层 | `server/routes/` → `server/services/` → `server/dao/` | 路由收参并校验权限，服务层写业务规则与事务边界，DAO 只做数据访问（字段走白名单、SQL 全用占位符） |
| 第三层 数据库 | `sql/01-schema.sql` 的 21 张表 + 连接池 | InnoDB + 外键 + 唯一键 + 逻辑删除；连接池与事务封装在 `server/db/pool.js` |

**为什么要分三层？**（面试/答辩高频）

1. 前端只关心展示，接口只关心协议，业务规则集中在服务层，改需求时影响面可控；
2. 事务边界清晰：缴费、角色授权、学生增删改都是「多条 SQL 要么全成功要么全回滚」；
3. 安全边界清晰：权限校验在接口层、数据白名单在 DAO 层，前端绕不过去。

## 三、演示脚本（建议按这个顺序点，约 5 分钟）

| 步骤 | 操作 | 讲解点 |
| --- | --- | --- |
| 1 | 打开 `login.html`，点「一键登录」 | 界面无账号、无密码、无角色选择；后端签发 JWT，权限码随令牌下发 |
| 2 | 落到「工作台」 | 数据概览、待办提醒（欠费 / 异常考勤 / 待点评作品由 SQL 实时推导，不额外建表） |
| 3 | 侧边栏顶部「切换子系统」 | 父系统下挂 7 个子系统，教学管理为完整实现，其余为演示入口 |
| 4 | 新闻中心，切换四个 Tab | 全部 / 平台公告 / 行业资讯 / 赛事动态；标签 + 分页器与参考图一致；无任何「奖学金」内容 |
| 5 | 学生管理 → 缴费管理 → 某条欠费点「确认收款」 | 收款金额实时重算欠费与状态，事务 + 金额校验（收款不能超过欠费） |
| 6 | 学生管理 → 学生考勤 → 「录入考勤」 | 按「学生 + 课程 + 日期」唯一键 UPSERT，重复录入自动覆盖，不会插重复 |
| 7 | 成绩管理 → 成绩录入 | 选班级 → 加载在读名单 → 批量打分 → 保存，走后端批量接口 |
| 8 | 系统管理 → 角色管理 → 「角色授权」 | 勾选权限保存后立即写库；超级管理员的权限在 JWT 里是 `["*"]` |
| 9 | 课件资源 → 「上传课件」 | 选文件真正走 multer 落盘，下载时后端累加下载次数 |
| 10 | 右上角个人中心 | 资料保存、修改密码（已是 bcrypt 哈希则校验原密码）、我的权限码清单 |

> 演示前先确认 `GET /api/health` 返回 `{ server:"ok", database:"ok" }`；
> 若数据库没启动，前端会自动降级到内置演示数据并显示黄色提示条，仍可完整演示界面与交互。

## 四、常见追问与回答

1. **一键登录会不会不安全？**
   一键登录解决的是「演示与内部使用的便捷性」，安全性由三件事保证：JWT 有签名与 7 天有效期、每个接口都用 `requirePerm` 校验权限码、前端只能拿到自己被授权的菜单与按钮。生产环境可在此基础上加设备指纹或二次验证。

2. **为什么前端不用 Vue / Element Plus？**
   作业要求前端只用 HTML、CSS、JavaScript。我们把侧边栏折叠、Tab 切换、表格、分页器、弹窗全部用原生 DOM 手写，并且做了公共组件层（`components.js`），增删一个页面只需要写配置。

3. **班级表为什么叫 `clazz`？**
   `class` 是 SQL 与多门语言的保留字，直接用作表名容易踩坑，所以统一命名 `clazz`。

4. **为什么用逻辑删除？**
   学生、教师、课程这类业务数据被成绩、考勤、缴费引用，物理删除会破坏历史数据一致性，因此业务表用 `deleted` 标记；考勤、评价、课程大纲这类流水/从表用物理删除，保证唯一键干净。

5. **成绩和考勤为什么不会重复录入？**
   表上建了唯一键：`uk_score(学生, 课程, 考试类型)`、`uk_attendance(学生, 课程, 考勤日期)`，服务层用 `INSERT ... ON DUPLICATE KEY UPDATE` 实现「有则更新、无则插入」。

6. **冗余字段怎么保证不脏？**
   `clazz.student_count`、`payment.arrears_amount` 属于刻意冗余（列表页免联表统计），由服务层在写操作中同步维护，例如学生增删改后立即重算班级人数。

7. **权限是怎么落到按钮上的？**
   权限表 `sys_permission` 用 `parent_id` 自关联成「目录 → 菜单 → 按钮」三级树；前端用登录时下发的权限码渲染菜单，并控制按钮显隐；后端接口再次校验，改了前端也调不通接口。

8. **为什么不引入 Redis？**
   一键登录用 JWT，服务端自校验签名即可，不需要会话存储；Redis 属于可选的性能优化项，课程作业阶段引入只会增加部署复杂度。

9. **怎么保证文档和代码一致？**
   项目里有 4 个自检脚本：SQL 脚本自检、前端自检（含内联脚本语法）、演示数据接口契约自检、后端自检（路由 vs 前端调用、权限码、DAO 字段映射 vs 建表脚本）；接口文档由路由源码自动生成。

10. **下一步准备做什么？**
    补消息中心与作品墙两个页面、把课程/大纲等剩余写操作接完、增加操作日志与登录日志、把课件与作品接入对象存储。

## 五、小组协作建议

- **一个工程、一份 Git 历史**：不要复制项目，所有迭代在同一个仓库里提交，提交信息写清「第 N 轮 + 模块」。
- **按模块分工**：前端页面（系统管理 / 学生 / 教师 / 新闻）、后端接口、数据库与文档三条线并行，接口以 `docs/03-后端接口清单.md` 为准。
- **每次提交前跑一遍自检**（4 条命令见 README 第 6 节），保证不会把红线和语法错误带进仓库。
- **红线清单**：项目名称只能说「编程培训平台管理平台」；登录页不得出现账号 / 密码 / 角色选择；新闻中心只有四个 Tab；**全站不得出现「奖学金」**。

## 七、演示环境准备（答辩前一天做一遍）

```bash
# 1) 建库与数据
mysql -u root -p < sql/01-schema.sql
mysql -u root -p < sql/02-seed.sql

# 2) 后端
cd server && cp .env.example .env    # 改好 DB_PASSWORD
npm install && npm start

# 3) 自检（应全部通过）
python tools/check_sql.py sql/01-schema.sql sql/02-seed.sql
node tools/check-web.js
node tools/check-api.js
node tools/check-server.js
```

浏览器打开 `http://localhost:3000/login.html` → 点「一键登录」→ 按第三节脚本演示。
